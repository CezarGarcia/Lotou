Keycloak · Authorization Code com PKCE

O login, passo a passo

A senha só é digitada na tela do Keycloak. O código que volta para a loja não serve para nada sem um segredo que só ela tem. Depois, cada chamada à API leva o token, conferido duas vezes.

Por que PKCE: só o hash passa pelo redirecionamento. Quem interceptar o código não tem o segredo, e o Keycloak recusa a troca (ADR 27).
O token é um JWT: um JSON assinado pelo Keycloak, com quem é a pessoa (sub) e os papéis dela. Conferir a assinatura não exige perguntar nada ao Keycloak.
Quem decide é o servidor: a loja esconde o que o papel não permite, mas é só conveniência. Gateway e serviço recusam de verdade.
